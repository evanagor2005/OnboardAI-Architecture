# Design decision records

These records explain significant **choices** about design or technology. They are separate from the team's [`adr/` architecture rules](../adr/README.md). Create one numbered file per consequential choice using the [template](TEMPLATE.md), such as `0001-data-storage-approach.md`.

A choice deserves a record when it changes the system's structure, affects several components or quality goals, creates a major dependency, or would be costly to reverse. A simple schema field or visual detail can remain in the design file.

Statuses: Proposed, Accepted, Superseded. If an accepted choice changes, add a new record and link the old one rather than silently rewriting its rationale.
